## Gotchas
- **Never put personal data in Sanity** (public-read dataset). Keep names/emails/addresses in Stripe/Clerk and fetch them server-side when needed.
- After about 2026-10-25, re-run an anonymous history check to confirm old revisions are gone (see the PRIVACY FIX note).

- Clerk's dashboard masks secret keys after creation; copy the full key from the Quick copy box or when creating a new key. A masked copy (`sk_test_…`) breaks auth with handshake/redirect-loop errors. `npm run check-env` detects this.
- `npm run check-env` validates `.env.local` (presence, ASCII, prefixes, length) without printing secrets. Run it after editing keys.
- Pages that read `params` keep the page component synchronous and read `params` inside `<Suspense>` with a skeleton (`components/product/skeletons.tsx`); otherwise dev shows an instant-navigation error.
- Repo conventions from the owner: commits are authored by the owner only (no co-author trailers), and docs must not mention any external reference project; all code is original.
- This Next.js version differs from training data: read `node_modules/next/dist/docs/` before writing Next code (see `AGENTS.md`).

- **No Dependabot (decided 2026-10-22).** The owner must be the only contributor, and merged Dependabot PRs put `dependabot[bot]` in the Contributors list, so `.github/dependabot.yml` was removed, its open PRs (#5 ESLint 10, #6 jsdom 30) were closed, and the four Dependabot commits already in history were re-authored as the owner (history rewritten and force-pushed on 2026-10-22; only the 12 commits after `266e4bb` got new ids, the owner's signed GitHub web commits were left untouched; GitHub now lists the owner as the only contributor). A local-only branch `backup-before-rewrite` keeps the old history; delete it when no longer wanted and never `git push --all` while it exists. Update dependencies by hand: `npm outdated`, bump, `npm install`, then `npm run lint && npm run typecheck && npm test`, and a production build with `npm run test:e2e` for anything big (React, Next). Never merge a bot's PR as-is or squash-merge it. CI still fails on critical advisories (`npm audit --omit=dev --audit-level=critical`). A Linux-made lockfile drops other-platform entries (e.g. `@typescript/typescript-*`): run `npm install` and commit what it restores. Use `git merge`, not `git pull --rebase`, when history has merge commits. `main` has a GitHub ruleset blocking force pushes and deletion (direct pushes are allowed); switch it to Disabled only for a deliberate history rewrite.
- **README badges:** GitHub's badge service showed "no status" for the plain URLs, so they use `?branch=main` (CI) and `?branch=main&event=workflow_dispatch` (End-to-end, which has only run by hand; once the daily scheduled run exists, consider `event=schedule`). Browsers and GitHub cache badge images for a few minutes after a change.
- **Lockfile and platforms:** `package-lock.json` was made on Windows and lacked `@emnapi/core` and `@emnapi/runtime`, so `npm ci` failed on Linux ("Missing ... from lock file"). Fixed by copying those two entries in. Regenerating the whole lock inside Linux instead breaks `npm ci` on Windows, so do not. After changing dependencies, verify both: `npm ci --dry-run` here, and in Linux with `docker run --rm -v <copy of repo>:/app -w /app node:24 npm ci --dry-run` (Docker Desktop must be running; use a copy of the repo, since a bind-mounted full install is very slow). If Linux complains about a missing entry, add just that entry to the lock.
